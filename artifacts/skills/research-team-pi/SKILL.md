# Research team

Research only: investigate unknowns, produce one synthesis shared by independent streams, and hand off without silently authoring specs/plans or seeding tickets. The coordinator surveys project instructions, existing evidence/source and current native state, defines independent questions and obtains or verifies the existing scoped grant before launch. A leaf never delegates. Optional web research reads web-research-pi with the required separately activated web tools; absent tools block that role, not permit silent substitution. Explicitly authorized local-source continuation must disclose the limitation; mandatory core web remains required.

## Scope and recovery

Act only within the task's current grant. Research, authorship, review, planning, execution, integration, publication and cleanup are separate actions. Existing explicit approval remains valid within its recorded root, outputs and revalidation conditions; do not ask again merely because the stage changed. Changed scope or destructive actions need revalidation. Before work and after compaction, reread the mandatory brief, native mission state, latest decisions and project instructions, then inspect current artifacts. A leaf never delegates, mutates native mission state or writes lessons. Only the coordinator does so when authorized. Use contact_supervisor need_decision/interview_request for a material unresolved choice and wait for the actual reply; steering delivery is not consent. Do not switch model, provider, protocol or isolation on failure.
## Prepare and launch

Use [RESEARCHER-TEMPLATE.md](RESEARCHER-TEMPLATE.md). Coordinator binds stable logical keys, descriptive labels, exclusive runtime output paths, mandatory resolved brief/native-state/project/skill reads and acceptance evidence. Record source root/revision/input hashes, owner, run/session/mission IDs, attempts/latest run ID, output hashes, current asks and decisions in the native mission state. Native mission state, receipts and status are the single recovery authority; persist required output bytes outside retention-managed worktrees. Inheritance flags grant discoverability, not proof of reading; require initial/resume acknowledgements.

Read the qualified pi-subagents guide and effective tools/roles before using one top-level async workflow. Await dependent runs.run results and ordered runs.all independent work, without child async:true when completion is needed. A receipt is not completion; all promises settle even on failure before transition or cleanup. Read saved bytes and structured verdicts, not reviewer prose. File-only returns are pointers to read. If write is absent, the child returns complete content for runtime persistence. Do not infer a file exists from task text or agent_end.

## Budgets and transitions

Record stage-specific concurrency, total-run, deadline, review-cycle and memory budgets BEFORE launch. This deployment caps a reviewer wave at four reviewers; a smaller available budget wins. Start with at most two useful lightweight lanes when measured headroom permits. This deployment reserves >=500 MB and refuses expensive admission below 750 MiB free OR available or unknown container headroom. Missing tools/setup stops for same-protocol recovery, no alternate runner/model. A clean final wave may close with zero spare waves/runs; remaining capacity is checked only when admitting an action that consumes it. New authorized stages use their own recorded budgets, not capacity borrowed from a finished stage.

For the requested NEXT stage check applicable authority (issuer/time/action/root/outputs/digests/revalidation), every required run settled, readable current output hashes, valid acceptance, reviews for those exact bytes, disposition of findings, no separate requirement/test/authority/release failure and no exceeded budget. Existing valid planning authority is not erased by the transition. Steering acknowledgment, exit 0, agent_end, self-attestation and acceptance.review alone do not satisfy this predicate; acceptance.review does not launch an independent reviewer.

Ignored/untracked/external inputs must be reread: use an uncached typed gate `{command, output: "json", schema}` or a verification invocation containing the expected digest AND checking it against the actual bytes. A fresh hash next to cached success is insufficient. Bind command, invocation identity, inputs and results. Changed reviewed bytes require correction disposition/fresh parent checks; at the review ceiling record old/new hashes without claiming reviewers saw the correction.

## Consume and synthesize

Coordinator reads EVERY findings artifact and confirms complete evidence/decomposition at the required barrier before one sole author synthesizes. Missing/partial input prevents full-consumption claims. Use [DELIVERABLE-TEMPLATES.md](DELIVERABLE-TEMPLATES.md): one effort/synthesis, one spec+plan per independent stream (ADR-0003). Plan fields remain null until authorized files exist; link actual native mission/receipt references rather than seed a second task graph. Respect actual project tracking; never add foreign ignore rules. Only coordinator writes shared metadata and [lessons](LESSONS-FORMAT.md) when authorized.

## Installed execution

Use workflow-research-pi for authorized local/web research, specification/plan synthesis and independent review with at most one reconciliation. Verify the installed workflow is version 1.1.0 and supports the opt-in schema before emitting a new selector; snapshot presence alone is not compatibility evidence. Until that verification succeeds, emit only the legacy request with `mode`, `snapshotUse`, and `liveChecks` omitted.

For a research-only grant, send `mode:"research-only"`, only requested local/web tasks, only their roles, native runner evidence, action `research`, `reconcile:false`, and one reserved spawn per task. Bind the parent-reread capability snapshot and current live authority, resource, output-claim, selected-capability, and settlement observations in `preflight.snapshotUse` and `preflight.liveChecks`. Local-only work carries no placeholder web task, role, tools, provider qualification, or web budget. Selected web work retains its separately authorized tool/provider/query/page limits and never falls back to local research. Consume the returned lifecycle records and read every settled findings output before any separately authorized synthesis. `awaiting-parent-synthesis` is pending parent work, not achieved specification, plan, review, acceptance, or next-stage authority.

Research-only tasks retain their narrower grant; no implicit planning or coding authority. The historical references/workflow-example.js and its fixture remain host-only examples, not a sandbox runtime or an alternate ledger. Never adapt that Node/FS example into a task-local substitute for the installed workflow.js. Native mission state/receipts/status are the sole task authority.

## Review disposition and authority

Normalize by consequence to **Critical / Major / Medium / Low**: catastrophic security/data-loss impact; substantial requirement/correctness/safety failure; bounded material defect; or presentation/low-impact improvement, respectively. Preserve original severity and every source finding ID under a canonical defect ID, with location, evidence, consequence rationale, proposed correction and unresolved status. Never mechanically convert Important to Major or Minor to Low, or downgrade severity to fit a threshold. A reduction needs concrete consequence evidence and a recorded parent disposition.

Use one fresh independent review and at most one bounded correction/disposition, not automatic two-cycle rituals. Unresolved Critical/Major findings block; Medium residuals need explicit owner acceptance. Preserve source finding IDs, consequences and old/new hashes. Required tests, authority, evidence and requirement coverage independently block. Corrected bytes are not retroactively independently reviewed; stop at the bound and return unresolved decisions to the parent.
