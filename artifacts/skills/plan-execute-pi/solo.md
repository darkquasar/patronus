# Solo execution

One authorized writer follows the plan sequentially. Before each task reread its brief, predecessor contracts and current native state. Implement only assigned files using the brief's recorded `critical-tdd` or `focused-postcheck` strategy and selection rules in SKILL.md. Missing or ambiguous strategy stops for a coordinator decision before editing. For critical TDD, read tdd-pi and use short public-behavior red/green slices plus negative/legacy regressions. For routine prose/manifests/mechanical wiring without a changed safety invariant, inspect the exact diff and positive/negative cases and run approved focused postchecks. Explicit test-first requests and project-required checks govern; preserve existing safety tests and never invent red cycles for prose. Inspect actual output and report strategy/rationale, applicable red/green or postcheck evidence and changed files/hashes. Only the coordinator updates native mission status after reading actual final outputs. Do not batch durable progress until the end or mark completion from memory.

Stop on missing prerequisites, unexplained test failures or unapproved design decisions; contact the supervisor and wait. Never implement in another task's tree to repair a failure. When all tasks settle, run the required full verification and ask the coordinator for the required fresh independent whole-change implementation requesting-code-review-pi pass. Small deliveries still require it unless the owner explicitly waives the gate. Supply recorded branch base/head, exact inputs and logs, not the author's transcript. Apply the normalized policy in SKILL.md; integration/publication/cleanup require separate grants. Hand off through finishing-a-development-branch-pi.
