# Independent task execution

Use workflow-implement-pi for disjoint writer lanes and select its phase-separated `write`, `integrate`, and `validate` operations after verifying opt-in capability. The parent reads the approved plan, resolves shared design decisions, binds exact source/base and exclusive file claims, verifies effective roles and authorizes managed cleanup before dispatch. Both upstream external writer identities are choices before launch, never recovery fallbacks. Leaves implement their bounded tasks and do not delegate. Legacy omission retains the all-in-one v2.6.0 graph for compatible callers.

Read every final report and captured upstream patch/handoff after writing. Before integration, independently read/hash declared targets, verify required semantics and pre/post identity, and compare the full authorized path set for unauthorized changes. Persist a passed target-delivery record before constructing the integration request. Repeat the same barrier against the retained integration checkout before validation or review. Report-only success, an unchanged required target, a wrong-target write, report-target divergence, drift, or an unauthorized sibling mutation blocks with zero dependent launches.

Validation selection belongs to the parent risk analysis. Default to parent-direct when suitable: it records deterministic evidence and launches zero validators. A bounded validator receives only its exact question, subject, concise context, checks, output, applicable limits, timeout, and stop conditions. Deep validation requires a prior shortfall plus explicit approval and never starts automatically. Failed, stopped, partial or missing evidence blocks dependents. Source is clean at each allocation; never stash/ignore/clean it to admit work. Durable outputs live outside source/integration/worktrees. Native mission state/receipts/status are the sole recovery authority. Each operation ends at its parent barrier; only the coordinator admits the next assignment.

Run one fresh independent aggregate review of exact bytes and tests using workflow-peer-review-pi. Select exactly one admitted reviewer with `reviewSelection`, record the approved single-reviewer policy in existing `reducedReviewEvidence`, and use `disposition:"parent"`. These compatibility fields do not demand a new owner-consent ritual. Do not omit them and accidentally launch every eligible peer plus a disposition agent. The coordinator reads complete findings, deduplicates without dropping IDs and admits at most one batched correction/disposition, not a fixer per finding or per-task review chain. An earlier review requires a named changed safety/compatibility invariant or irreversible boundary with a separate acceptance point; it never replaces aggregate review. No retrospective review claims for corrected bytes or automatic second wave. Required tests, authority and coverage remain gates. Publication and retained-checkout cleanup require their own grants.
