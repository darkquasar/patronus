# Spec brainstorming

Explore intent, constraints and success criteria before implementation. Read existing synthesis and every supplied findings artifact first; do not rerun settled research. Confirm the implied design when evidence is complete; otherwise ask the unresolved questions one at a time. Separate unknown-domain research (research-team-pi under its own grant) from decomposition of known independent streams. Optional grilling-pi may stress-test the design within authority.

## Scope and recovery

Act only within the task's current grant. Research, authorship, review, planning, execution, integration, publication and cleanup are separate actions. Existing explicit approval remains valid within its recorded root, outputs and revalidation conditions; do not ask again merely because the stage changed. Changed scope or destructive actions need revalidation. Before work and after compaction, reread the mandatory brief, native mission state, latest decisions and project instructions, then inspect current artifacts. A leaf never delegates, mutates native mission state or writes lessons. Only the coordinator does so when authorized. Use contact_supervisor need_decision/interview_request for a material unresolved choice and wait for the actual reply; steering delivery is not consent. Do not switch model, provider, protocol or isolation on failure.
## Design

Compare two or three approaches with tradeoffs and recommend one. Present architecture, components, data flow, failure handling and verification at proportional depth. Use compact ASCII structure diagrams when they clarify a boundary. Prefer small interfaces and existing conventions; do not smuggle unrelated refactors into design. Existing explicit design/authorship approval is sufficient within scope. Obtain decisions on actual unresolved choices, not repeated ceremonial approval.

## Author (ADR-0003)

Use the project's research-effort layout and tracking rules, not a foreign plugin layout or automatic gitignore edit. One effort has one synthesis, and each independent stream one spec and one plan. Coordinator owns shared meta.yaml. Name a spec only when its authorized file exists; plan stays null until written. Link actual upstream mission/receipt references, not a second task graph. Record a user-declined spec explicitly rather than invent it. Validate parsed metadata against actual files in both directions.

Write testable requirements with IDs, scope/non-goals, interfaces, failure/rollback, authority and evidence limits. Self-check placeholders and contradictions. Use [spec-document-reviewer-prompt.md](spec-document-reviewer-prompt.md) as an input to authorized spec-review-pi, not a separate unbudgeted review loop. Spec authors are leaves and return their complete artifact to the coordinator. Spec completion never silently starts planning or coding; an existing valid planning grant can permit the next stage after the evidence gate.
