# Code provenance

The coordinator records spec-to-file traceability in an authorized existing report
or provenance.md alongside the stream spec. This is evidence, not another mutable
progress authority. Teammates return exact changed-file information and never write
shared provenance or source headers.

Record each material changed file's project-relative path, spec/plan requirement
or task anchor, summary and captured byte/patch identity. Ticket IDs are optional
and used only when tk is selected; no automatic ticket seeding. Match records to
settled integrated bytes, not status or branch existence. A compact table helps
repeated mappings. Use rg for lookup. No Git tracking, publication or cleanup is
implicit.
