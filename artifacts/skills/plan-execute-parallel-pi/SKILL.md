# Execute independent file-owning lanes with serial consumption barriers

## Scope and recovery

Act only within the task's current grant. Research, authorship, review, planning, execution, integration, publication and cleanup are separate actions. Existing explicit approval remains valid within its recorded root, outputs and revalidation conditions; do not ask again merely because the stage changed. Changed scope or destructive actions need revalidation. Before work and after compaction, reread the mandatory brief, native mission state, latest decisions and project instructions, then inspect current artifacts. A leaf never delegates, mutates native mission state or writes lessons. Only the coordinator does so when authorized. Use contact_supervisor need_decision/interview_request for a material unresolved choice and wait for the actual reply; steering delivery is not consent. Do not switch model, provider, protocol or isolation on failure.
## Admission

Only the coordinator routes work. Read the actual spec/plan/native-state and source contracts; authorize each independent decision and exclusive output. Overlapping files or dependent choices stay sequential. Select the largest useful independent ready set within measured free/available RAM and container headroom, initially at most two lightweight children on 2CPU/4GiB. Record concurrency, total runs, deadline, resource reserve and expensive-job lock separately; this deployment uses >=500 MB reserve and no expensive admission below 750 MiB free OR available. Unknown headroom means bounded source reads/sequential work if already authorized, otherwise escalation. No mandatory fanout count.

Verify pi-subagents is delivered, separately activated and its effective roles/tools/provider loading are qualified. No implicit installation or builtin substitute. Use one parent top-level async workflow, stable task keys and descriptive labels. Inside it await runs.run dependencies; use await runs.all only for independent items and consume its ordered results. Omit child async:true when the next stage needs completed output: a dispatch receipt never satisfies acceptance. Track every promise through failure; no transition or cleanup while any remains unsettled.

## Isolation and output

Read using-git-worktrees-pi before writer launch. Choose clean named-base native capture with exact prelaunch deletion grant OR coordinator-retained cwd when retention/private-LSP approval is needed. Each leaf has one isolated owner, its complete mandatory brief/native-state/project/skill reads, exact file boundary, expected source/base/output hashes, budgets and stop conditions. Bind exclusive outputs through runtime output, not task prose alone. If write is unavailable return full content for runtime persistence; the parent reads saved bytes even when file-only mode returns a pointer.

Record source revision, stable keys, run/session/mission IDs, owners, output hashes and decisions in upstream native mission state and receipts, the sole task/execution authority. Leaves never claim unrelated work or mutate shared state. After compaction inspect latest status and read output bytes before a bounded same-protocol action. No model/provider/runtime fallback or competing ledger.

## Consume, verify delivery, review and integrate

Verify settled run status, actual readable hashes, structured acceptance and exact-byte review. Child completion, reports, structured output, verdicts, `outputReference`, and success prose settle only the child-output obligation. Before any dependent integration, review, validation, publication, or other successor, the coordinator independently applies the declared-target delivery barrier:

1. Read and hash every exact declared target from its authorized location.
2. Bind every target to its pre-run identity and required post-run change or deterministic postcondition.
3. Verify required syntax, structure, and task-specific semantics against actual target bytes.
4. Compare complete authorized path and source-status observations before/after for unauthorized additions, modifications, or deletions.
5. Compare report claims with actual target bytes and record divergence.

A missing target, unchanged target when change was required, malformed target, wrong-target write, report-target divergence, preidentity drift, or unauthorized sibling mutation creates blocking delivery evidence and zero dependent launches. Preserve the report, hashes, path observations, and unknown ownership state. Do not repair or broaden a child task while applying this gate, and do not create a generic delivery framework.

A blocked lane stops its dependents; independent work may continue only under its own grant. Coordinator deduplicates concrete findings and dispositions one fresh review with at most one bounded correction; unresolved blockers and required test/authority/evidence failures block. Clean final closure needs no spare wave. At the ceiling record correction hashes and parent verification, not invented rereview.

Integration is a separately granted serial stage after durable handoffs and passed declared-target records, with fresh tests on the aggregate. Publication and discard remain separate. Capture failure, drift or unknown processes/ownership retains work. Report exact changed files, checks and limitations, not reviewer prose parsed as success.

Use the installed workflow-research-pi, workflow-implement-pi or workflow-peer-review-pi for these stage graphs. Do not substitute an effort-specific generated orchestration. Native completion notifications replace polling; bounded bg_wait is only for runtimes without notification support.
