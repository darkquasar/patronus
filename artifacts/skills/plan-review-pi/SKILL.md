# Review exact plan coverage, ordering and interfaces before execution

Use the owner's selected destination and established project layout throughout.
Any `docs/specs/NN-slug/` path below is a default example, not a location
requirement; preserve the selected effort's metadata and stream relationships.

One independent written-plan reviewer is required, including for one task, unless the owner explicitly declines that subject and the existing brief records it. The coordinator supplies the plan AND the spec it implements, or the recorded explicit spec-decline exception. Read [plan-reviewer.md](plan-reviewer.md). Review is evidence, never execution or publication authority.

## Semantic review boundary

Check actual spec-to-plan fidelity, inherited constraints versus planner choices,
requirement/task/check links, vocabulary/boundary/invariant preservation and
reasoned start/join deliverables. Runtime order alone is not build order; inspect
accepted inputs, ownership, isolation and settlement before accepting parallelism.
Review unsupported verification burdens/gates against recorded owner policy;
subjective comparison ratings alone do not block. Report feasibility without
choosing execution mode; retain the existing independent-review disposition.


## Scope and recovery

Before work and after resume, read the current brief, selected progress authority, latest decisions and effective project instructions, then inspect actual source and retained outputs. Existing valid approval continues within scope; changed scope or a real unresolved choice needs coordinator decision. Leaves return complete evidence and stop, without delegation or shared-state writes. Stage completion admits no successor, publication or cleanup. No silent model/provider/protocol/isolation fallback.
## Independent review packet

Coordinator only: inspect actual available native roles, tools, providers and permissions before launch. Use a fresh-context read-only reviewer with explicit context/skill inheritance, mandatory resolved brief/native-state/project reads and an exclusive runtime-bound output. Give exact source root/revision and input/output hashes, constraints and test evidence, not the author's reasoning transcript. Missing tools or inactive pi-subagents blocks delegated review, with no builtin, runner or model substitution. Preserve the selected provider and full mandatory skill union when selecting a code-review rubric. Read the saved bytes and structured acceptance before disposition. A self-review is useful but cannot replace required independence.

Report skipped lenses and unverified claims. The parent verifies every material finding against current source and records accept/reject/defer reasons. No author transcript, self-attested pass, agent_end or exit 0 alone satisfies a gate.

## Review disposition

The substantive coverage/ordering/interface rubric and L2 consequence-based acceptance contract live in plan-reviewer.md. Reviewers return findings and stop. The coordinator chooses execution mode and progress authority once, reads complete reports and admits at most one batched correction/disposition. No automatic dual-model review, successor chain, shared-state update or repeated consent.
