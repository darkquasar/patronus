# Finishing a Development Branch

Consume the accepted implementation evidence, do not restart its lifecycle.
Announce this handoff, then read the current brief, latest decisions and source.

## Check the handoff

Use verification-before-completion-cl to compare exact final inputs, commands,
environment, scope, readable logs and actual exits. Relevant dirty/untracked/
ignored inputs count. Matching integration evidence satisfies finishing without
another identical suite; final composed aggregate checks stay fresh. Missing
requirements, authority, checks or independent aggregate review blocks acceptance.

Confirm all workers are settled and complete reports/patches captured. Unknown
liveness, ownership or capture retains the work and blocks integration/cleanup.
Use receiving-code-review-cl for the existing one-batch disposition, not a new
reviewer or correction wave. Critical/Major or more than two Medium remain blocking;
up to two Medium residuals require explicit owner acceptance.

## Choose only the needed action

Inspect actual root, current branch, allocated worktree and approved base. A
detached HEAD or externally managed workspace must not be guessed into a merge.
Existing valid grants remain valid within their scope; a stage label alone does
not require renewed consent.

If no integration/publication action is granted, return the captured handoff and
preserve branch/worktree. When the owner asks how to land it, explain feasible
choices and consequences: keep the captured branch, integrate locally, or publish
a PR if remote authority exists. Ask only for the unresolved choice. Do not impose
an exact menu or offer discard as routine completion.

Integration, commit, remote publication and destructive cleanup are separate
grants. A local merge request does not imply pull/rebase/push or branch deletion.
Check actual merge inputs and run affected composed checks for changed results.
A failed merge/push is reported with partial evidence, not retried until success.

## Explicit cleanup only

Before separately authorized cleanup, resolve exact paths/branches and creation/
ownership records. A directory name such as worktrees/ does not establish ownership.
Ensure complete captured evidence, successful required checks and worker settlement.
Never remove a host-managed allocation or prune unrelated registrations.
Destructive discard needs clear target-specific owner confirmation; preserve
recoverable patches/results first. Do not run removal from inside its target.
Retain work when capture or settlement is uncertain.

## Return

Report root/base/head, branch/worktree, changed files and hashes, actual check
commands/exits/logs, review/disposition identity, limitations, open choice and next
authorized action. Do not claim publication from local checks. No automatic push,
pull, rebase, stash deletion, branch/worktree removal or prune.
