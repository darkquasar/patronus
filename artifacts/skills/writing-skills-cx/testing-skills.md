# Bounded skill evaluation

This is a method, not a launch grant. Do not spawn workers or make model/API calls
automatically. A leaf returns proposed cases; only the lead can approve and run a
campaign using existing runtime tools. Do not build another testing framework.

Before testing record: approved skill bytes/hash, hypothesis, baseline/control,
case names, scoring rubric, maximum calls/repetitions, concurrency, timeout,
spend/resource budget, output bindings and stop condition. No unlimited
"bulletproofing" loop. Missing runtime/auth/capabilities block without fallback.

| Type | Case | Oracle |
|------|------|--------|
| Discipline | deadline plus pressure to skip a guard | preserves the guard and reports a block |
| Technique | a new scenario and a missing prerequisite | applies steps and identifies missing input |
| Pattern | positive and counter-example | chooses the model only when appropriate |
| Reference | retrieve a field and follow a local reference | finds the correct shipped file/value |

Compare the same invented case without and with the candidate guidance. Preserve
exact outputs, rationalizations, hashes and exits. A baseline that does not
exhibit the proposed failure cannot prove the skill repaired it. Review each
flagged match manually; echoes of a rule are not actions. Never present simulated
quiz responses as observed production behavior. If fresh-context native testing
is not authorized, perform the allowed local audit and disclose the runtime gap.

Classify a failure before correction: safety violation, wrong output shape,
omitted field or condition misread. Make a targeted change within file ownership.
Use the approved bounded correction and stop at its limit. Preserve previous
failed evidence. Asking the owner is a valid safety outcome, not a loophole to
penalize. No coercive "choose and act on production" prompts or automatic source
deletion. Use `{skillsDir}/tdd-cx/SKILL.md` for code-behavior testing vocabulary.
