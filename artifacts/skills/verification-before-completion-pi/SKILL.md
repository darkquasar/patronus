# Evidence before completion

This skill grants no execution, edit, delegation, commit, publication or cleanup authority. Use approved checks and applicable host/resource limits. Missing tools or authority produce blocked/unverified checks, not assumed passes. Do not install or broaden access to obtain evidence.

Before any completion, passing or fixed claim:

1. Identify the full command or deterministic observation proving this claim.
2. Bind exact relevant checked bytes, including dirty, untracked and ignored inputs, full command/options, dependencies, tools/environment and acceptance scope. HEAD equality alone is insufficient.
3. Read complete saved output and actual exits, including failures. Reuse only when all relevant identity and readable logs still match. Message or stage names alone do not invalidate evidence; relevant drift, changed acceptance, missing logs or unknown identity do. Rerun the authorized check or report it blocked.
4. Compare observations with the criterion, then report hashes, command, exit, log and skipped coverage. Child receipts, success reports, structured verdicts and filenames are not acceptance. Read actual declared targets, complete reports and captured patches before dependent consumption.

Final aggregate verification stays fresh for composed final inputs. Matching integration checks can satisfy finishing without an identical extra suite. Passing leaf tests do not prove the aggregate or requirement coverage. One independent aggregate review can satisfy matching branch/pre-merge/finishing triggers, without a new review for an unchanged subject. Self-checks are not independent review.

Follow the approved strategy and tdd-pi defaults. Critical auth/secrets, ownership, concurrency/isolation/settlement, migration/removal and reproducible behavior bugs require intended invented-data public-behavior red, minimal green and relevant negative/legacy regressions. Other features and behavior changes default to the same TDD loop; a different strategy needs a concrete reason and owner agreement unless task/project policy already approves it. Pure behavior-preserving refactors stay green on existing coverage and characterize uncertain legacy behavior before restructuring. Routine prose/manifests/mechanical wiring without a changed safety invariant use focused postchecks, with no invented red or prose-substring tests. Explicit test-first requests and project checks govern. If strategy is absent, record selection from these defaults in the existing brief/handoff; only genuine classification conflicts or proposed exceptions need an owner decision. Valid approval is not reconfirmed per slice.

Required tests, authority, requirement coverage and independent aggregate review remain gates. Fixed defects need the cited-defect/exact-byte/positive-negative-regression oracle, labelled parent-verified rather than independently re-reviewed. Changed public interfaces, safety invariants, acceptance scope or insufficient proof need an owner decision or additional grant. Preserve partial evidence and unresolved findings.

Mandatory initial and post-compaction brief, native-state and instruction reads remain required. Return root/base/head, changed files/hashes, actual checks/exits/logs, dispositions, skipped coverage, residual risks and next authorized action. No publication, cleanup or native compliance claim follows from local fixtures.
