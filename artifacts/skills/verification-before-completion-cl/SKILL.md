# Verification Before Completion

Evidence precedes claims. This skill grants no command, edit, Git, publication or
cleanup authority. Read the approved verification strategy and commands.

## Claim gate

1. Identify the authorized full command/options that proves this exact claim.
2. Compare checked bytes, including relevant dirty/untracked/ignored inputs,
   dependency/tool/environment identity and acceptance scope with retained evidence.
   HEAD equality alone is insufficient. A new message or stage name is not staleness.
3. Reuse a matching observed run only with readable complete logs and actual exit.
   Relevant drift, changed acceptance, unknown identity or missing logs invalidates
   reuse: run the authorized check or report the exact blocker.
4. Read complete output and actual exit, compare to the criterion, then state a
   bounded result with input identity, command, log reference and limitations.
   Nonzero/missing evidence is not a pass.
5. Keep final aggregate verification fresh for composed final inputs. Integration
   evidence may satisfy unchanged-input finishing with matching coverage.

## Coverage and strategy

A linter does not prove a build; a leaf test does not prove integrated consumers;
a status or filename does not prove delivered requirements. Read complete settled
worker reports and patches, and bind review evidence to exact delivered bytes.
Missing independent review, requirements or authority remains a separate blocker.
Use one selected progress authority, not another checklist/todo or attestation index.

Follow explicit test-first requests and required project checks. Critical
auth/secrets, ownership, concurrency/isolation/settlement, migration/removal and
reproducible bugs need intended public-interface RED, minimal GREEN and negative/
legacy regressions through tdd-cl. Other features/behavior default to TDD; if
strategy is absent apply and record that default, not a manufactured stop.
Exceptions need a concrete reason and owner agreement unless already approved.
Pure refactors stay green; characterize uncertain legacy first. Nonbehavioral
prose/manifests/mechanical wiring use focused postchecks. Real classification/
exception ambiguity needs an owner decision. No invented red cycle, prose-
substring ritual or automatic reviewer merely because tests exist.

For a fixed defect, verify cited defect, exact corrected bytes and sufficient
positive/negative/regression oracle against existing acceptance. Label corrected
bytes parent-verified, not independently re-reviewed. Changed public interface,
safety invariant or acceptance scope, or insufficient proof, needs owner decision/
additional review grant. Do not silently inherit old independent review coverage.

Report files, actual checks/exits/logs, hashes, disposition, skipped coverage and
next authorized action from existing records. Preserve partial evidence on failure.
No duplicate suite/reviewer merely for unchanged finishing, and no automatic
commit, push, merge, worktree removal or discard.
