# Review the exact spec against evidence before planning

Use the owner's selected destination and established project layout throughout.
Any `docs/specs/NN-slug/` path below is a default example, not a location
requirement; preserve the selected effort's metadata and stream relationships.

Use one independent reviewer for the exact written spec unless the owner explicitly declines that subject under the recorded owner-declined-spec exception. The coordinator supplies the spec and source evidence. Read [spec-reviewer.md](spec-reviewer.md). Review is evidence, never execution or publication authority.

## Semantic review boundary

Check necessity and sufficiency of outcomes, true constraints, failure guarantees
and structural goals for planning; flag unsupported private design and missing
behavior, DDD consultation/applicability or consequential owner decisions. Preserve
justified public technical detail and selective modeling. Review verification
burden/gates against owner provenance without inventing new thresholds. The rubric
contains the full contract; subjective comparison ratings or unavailable runs
alone create no blocker. Existing objective checks and disposition rules remain.


## Scope and recovery

Act only within the task's current grant. Research, authorship, review, planning, execution, integration, publication and cleanup are separate actions. Existing explicit approval remains valid within its recorded root, outputs and revalidation conditions; do not ask again merely because the stage changed. Changed scope or destructive actions need revalidation. Before work and after compaction, reread the mandatory brief, native mission state, latest decisions and project instructions, then inspect current artifacts. A leaf never delegates, mutates native mission state or writes lessons. Only the coordinator does so when authorized. Use contact_supervisor need_decision/interview_request for a material unresolved choice and wait for the actual reply; steering delivery is not consent. Do not switch model, provider, protocol or isolation on failure.
## Independent review packet

Coordinator only: inspect available native roles, tools, permissions and providers before launch. Use a fresh-context read-only reviewer with explicit context/skill inheritance, mandatory resolved brief/native-state/project reads and an exclusive runtime-bound output. Give exact source root/revision and input/output hashes, constraints and test evidence, not the author's reasoning transcript. Missing tools or inactive pi-subagents blocks delegated review, with no builtin, runner or model substitution. Preserve the selected provider and full mandatory skill union when selecting a code-review rubric. Read the saved bytes and structured acceptance before disposition. A self-review is useful but cannot replace required independence.

Report skipped lenses and unverified claims. The parent verifies every material finding against current source and records accept/reject/defer reasons. No author transcript, self-attested pass, agent_end or exit 0 alone satisfies a gate.

## Review disposition and authority

Normalize by consequence to **Critical / Major / Medium / Low**: catastrophic security/data-loss impact; substantial requirement/correctness/safety failure; bounded material defect; or presentation/low-impact improvement, respectively. Preserve original severity and every source finding ID under a canonical defect ID, with location, evidence, consequence rationale, proposed correction and unresolved status. Never mechanically convert Important to Major or Minor to Low, or downgrade severity to fit a threshold. A reduction needs concrete consequence evidence and a recorded parent disposition.

Use one independent reviewer per exact subject and at most one batched bounded correction/disposition, with no automatic reviewer/fixer successors. Unresolved Critical/Major or more than two distinct Medium findings block; one or two Medium residuals require explicit owner acceptance, never coordinator self-approval. Low findings receive recorded disposition. Required tests, authority, evidence and requirement coverage independently block. Preserve source IDs, consequences and old/new hashes.

The coordinator may resolve a fixed defect only by checking the cited defect, corrected exact bytes and sufficient relevant positive, negative and regression evidence against the existing acceptance criterion. Retain that evidence in the original report as parent-verified, not independently re-reviewed. A changed public interface, safety invariant or acceptance scope, or an oracle insufficient to prove defect removal, stops self-clearance and needs an owner decision or additional independent-review grant. Critical/Major residuals cannot be waived into acceptance. Stop at the correction bound and return unresolved decisions; focused edit/test iterations inside the granted batch are not new review waves.
