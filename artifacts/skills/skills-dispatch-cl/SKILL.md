# Skills Dispatch

Read requested and applicable installed skills before acting. Consider the whole
installed set, using descriptions for routing, not speculative one-percent fanout.
In Claude Code use the native Skill mechanism when available. Exact sidecar reads
use their installed bundle paths. Do not substitute foreign-harness or old-name
siblings. Missing required routes/tools stop the affected lane, not provider fallback.

System/developer constraints and effective user/project instructions retain their
actual priority; a skill cannot override them or grant edits, agents or Git actions.
Choose the smallest relevant set. Process guidance routes unknown research,
approved design, planning, execution or diagnosis, without restarting completed
stages. A valid accepted plan is not a request to brainstorm it again.

## Coordinator and leaf routes

The coordinator alone admits agents, reviews, corrections and successor stages.
Leaves read relevant guidance within their exact assignment, return full evidence
and stop. No nested fanout or shared progress mutations. Check actual tools,
permissions/auth, read-only roles, isolation and wait/stop controls before use.
Concurrent writers require disjoint isolated ownership and settlement before
serial integration. No required CLI supervisor for native delegation.

One independent review per distinct spec/plan/aggregate implementation subject,
not automatic task reviewers or second-model discovery. Inline author checks
remain inline. Use plan-review-cl, spec-review-cl and requesting-code-review-cl
for their actual subjects. Existing explicitly retained decline exceptions apply.

## State and recovery

Consume the sole progress authority recorded at plan acceptance: run-owning native
state wins; without it use explicit project selection, existing tracker or one
durable plan-associated record. UI todos alone do not outrank the project tracker.
Never expand skill checklists into todos, mirror tk, or create another ledger.
Metadata indexes artifacts; logs retain observations. Respect ignore/tracking policy.

Initially and after resume read effective instructions, approved brief, latest
handoff and actual source/results. Do not replay settled work or copy growing
history into leaves. No mandatory numerical root start/concurrency/deadline forms;
existing host/resource and separately authorized campaign limits remain applicable.

## Small handoffs

Explain real consequences and material assumptions in plain language, not opaque
ledger IDs. Ask only for changed scope or a genuine unresolved choice. Preserve
valid approval across stage labels. Named safety/compatibility boundary review
does not waive aggregate review. Verification-before-completion-cl owns matching
evidence reuse and final composed freshness; finishing consumes it without a new
suite or reviewer just for another message. Publication and cleanup stay separate.
