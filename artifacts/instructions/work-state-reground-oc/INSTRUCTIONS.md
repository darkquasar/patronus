# Recover OpenCode work context (advisory, no hook)

Initially and after resume/compaction, reread the approved brief, latest lead
handoff/decisions and effective project instructions. Inspect actual source
root/base/head, dirty/untracked state, stage grants, file owners, predecessor
settlement, applicable existing host/resource or campaign limits and saved output
bytes/hashes. No numerical root-budget form or cumulative start ledger is required.
Read project lessons where actually present. Report drift; never infer a grant
from stale chat history.

OpenCode has no task-specific mission API assumed here. Recover from the sole progress
authority already selected in the accepted brief: qualified native state that
actually owns delegated runs first; without it, explicit project/owner selection,
otherwise the existing tracker or one durable plan-associated record. Native UI
todos alone do not outrank a project tracker. Other records reference this authority
without mirroring mutable status. Use available native worker status/wait controls
and report actual capability or auth limits, without a blanket qualification
ceremony. Read every returned report and patch before treating work as delivered.
A status, filename
or dispatch receipt cannot substitute for the complete artifact.

Do not replay completed work, relaunch a live worker, overwrite another owner's
outputs or create a competing scheduler/tracker. Only the authorized lead updates
the selected shared progress authority and admits workers, modes and transitions.
Leaves return evidence and stop without successors, review chains or status writes.
Existing grants remain valid within scope; a changed stage name alone requires no
new consent. Changed scope, destructive action or material choice needs revalidation.
Reuse retained verification only when exact relevant inputs, command/options,
dependency/tool/environment identity and acceptance scope still match and logs/exits
remain readable. Final aggregate checks stay fresh for composed delivered inputs.
Missing state, unclear liveness or required persistence failure blocks continuation;
preserve partial evidence
and ask the lead. Never silently change model/provider/protocol/isolation.

This is advisory recovery guidance read by the model at session start through
the project instructions. OpenCode has no Patronus session-start hook here: no
automatic loader, background polling process or guarantee of always-on
continuation stands behind it.
