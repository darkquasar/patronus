# Optional Pi code intelligence

Before code-intelligence work, read the installed `pattern-mcp-pi`, `graphify-pi`
and `code-intel-operations-pi` skills. Static installation is **placed,
runtime-unverified**: it does not grant tools, connect services, approve project
resources, augment native roles or build an index. Core remains usable without MCP.

Discover the effective adapter tool names and schemas. Initialize Serena using
its discovered `initial_instructions` operation before symbol work; verify its
canonical project root. Prefer `find_symbol` and `find_referencing_symbols` for
live definitions/callers. Never activate a different shared project or mode.
Known file:line reads remain valid; unavailable tools mean disclosed source reads,
not new servers, resolvers or automatic repair.

Research/specification/review/plan children query coordinator-owned shared HTTP
services only. An execution writer uses source reads unless separately approved
for private Serena/LSP in its exact owned worktree. Shared symbols are main-root
symbols, not unmerged worktree symbols. Shared Graphify always describes a labeled
main snapshot: inspect revision, dirty/untracked treatment and coverage; verify
consequential EXTRACTED **and** INFERRED edges against current source. A missing
node or graph cannot prove code absence. Children never refresh or build graphs.

Base core role definitions remain unchanged. An operator must separately review
complete native role tool/skill/extension plans, approve the effective scope and
smoke-test actual capability before MCP-dependent dispatch. A skill name or
frontmatter tool name does not load an extension or widen a strict allowlist.
Retain core authority, output, acceptance and no-nesting limits.
