title: "Deploy the Pi core profile"
description: "Install native roles, workflow skills and pinned Pi extensions."
---

`core-profile-pi` 2.0.0 combines development, planning, review, research and
editorial skills with eight native roles and three workflow skills.

## Prerequisites

Install Pi and Node separately, and make Pi available on `PATH`. The selected
extension sources are `npm:pi-subagents@0.72.1` and `npm:pi-web-access@0.35.0`.
Pi/npm own the extension files; Patronus owns the authored resources it deploys.

## Deploy globally

```sh
patronus install --profile core-profile-pi --target pi --global
patronus install --profile core-profile-pi --target pi --global --deploy --allow-package-installs
```

The global root is `PI_CODING_AGENT_DIR` when set, otherwise `~/.pi/agent`.
Native installation can execute npm lifecycle scripts. Review the package plan
before granting package installation.

## Deploy to a project

First establish the compatible global extension packages, then run from the
selected project:

```sh
patronus install --profile core-profile-pi --target pi --local
patronus install --profile core-profile-pi --target pi --local --deploy --allow-package-installs --allow-pi-project-config
```

Local resources live under `.pi/`. Conflicting global and local authored identities
must be resolved before deployment. Identical exact npm sources follow Pi's
project precedence.

The installation flag authorizes writing the selected project configuration.
Pi runtime trust is separate: approve the project through Pi when needed, then
restart or reload Pi to discover the installed resources.

## Roles and workflows

| Role | Purpose |
|---|---|
| patronus-researcher-pi | Source research |
| patronus-web-researcher-pi | Web research |
| patronus-spec-author-pi | Specification drafting |
| patronus-plan-author-pi | Plan drafting |
| patronus-plan-reviewer-pi | Plan review |
| patronus-technical-reviewer-pi | Technical review |
| patronus-workflow-security-reviewer-pi | Workflow security review |
| patronus-writer-pi | Editorial writing |

The workflow skills are `workflow-research-pi`, `workflow-implement-pi` and
`workflow-peer-review-pi`. Read their installed skill instructions before launch;
they describe required inputs, output placement and review steps.

`workflow-implement-pi` accepts 1–10 writer tasks and concurrency of 1–10.
Set the outer `globalConcurrencyLimit` to the request's `concurrency`, and
reserve two spawns for integration and validation: ten writers need
`spawnLimit: 12`. Choose useful independent lanes within measured resource
and provider limits; keep expensive tests serialized under the project lock.
The model-free fixtures exercise a scheduler peak of ten. Live provider and
host capacity require separate qualification.

Native writer tasks may set `model` to an exact `provider/id` from
`subagent({action:"models"})`, optionally with a supported thinking suffix.
For example, independent `engine:"native"` tasks can select
`anthropic/claude-opus-4-8` and `openai-codex/gpt-6.1-sol` while using the same
writer role. The parent must verify model access, authorization and budget.
Omitting `model` preserves role defaults; integration and validation keep their
own defaults. External CLI tasks reject this field. Native model access and
Claude/Codex CLI runtime qualification are separate gates.

## Optional code intelligence

```sh
patronus install --profile code-intel-pi --target pi --global
```

Inspect that overlay's plan and its required services before deployment. It does
not replace the core profile or grant access to external services.
