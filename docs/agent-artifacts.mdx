Agent artifacts describe a role's instructions and target-specific settings.
Patronus deploys those definitions; your harness supplies execution, model access
and tool availability.

## Select a target

```sh
patronus install patronus-researcher-pi --target pi --global
```

Inspect the plan, then add `--deploy` to place the role. Different harnesses have
different role formats and supported settings; select content intended for your
target rather than assuming every role is portable.

## Pi role example

Pi roles deploy to `<agent-dir>/agents/<identity>.md` globally or
`.pi/agents/<identity>.md` locally. Core roles use `npm:pi-subagents@0.72.1`.
A representative native definition looks like:

```markdown
---
name: patronus-researcher-pi
description: Research source code and return grounded findings.
tools: read, grep, find, ls
---
Read relevant sources and report findings with references.
```

Installed core role definitions include their own skill and tool selections.
Inspect the effective role in Pi before launching it, especially when you use
operator overrides. A read-only prompt or role name does not create operating
system containment.

## Updates and removal

Use explicit scope for Pi role lifecycle operations:

```sh
patronus update patronus-researcher-pi --target pi --global
patronus remove patronus-researcher-pi --target pi --global
```

Apply with `--deploy` after reviewing the plan. Ordinary removal preserves edited
or profile-tracked content. Review sharing before using `--force`.

For the complete role set and required extensions, see [Pi core](/pi-core).
