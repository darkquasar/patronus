---
title: "Harnesses and scope"
description: "Choose the destination for your agent resources."
---

Use `--target` to select a harness and `--global` or `--local` to select its scope.
Global content belongs to your user environment; local content belongs to the
current project.

```sh
patronus install agent-principles --target claude --local
patronus install agent-principles --target codex --local
patronus install agent-principles --target opencode --local
```

## Default skill destinations

| Harness | Global | Project |
|---|---|---|
| Claude Code | `~/.claude/skills/` | `.claude/skills/` |
| Codex | `~/.agents/skills/` | `.agents/skills/` |
| OpenCode | `~/.config/opencode/skills/` | `.opencode/skills/` |
| Pi | `~/.pi/agent/skills/` | `.pi/skills/` |

`CODEX_HOME` changes Codex config/instruction/hook roots, not its skill root.
`OPENCODE_CONFIG_DIR` and `PI_CODING_AGENT_DIR` can change their selected roots.
Inspect the preview before deployment. Recorded legacy Codex skill roots require
a separately authorized `patronus migrate codex-skills` preview/deploy, not force.

## Target-specific support

Harnesses differ in agent-role formats, settings, hooks and prompt support.
Patronus adapts supported content to the selected layout; it does not supply a
universal tool or permission model. An artifact's declared targets determine where
it can be installed.

Use `patronus scan` to inspect detected harnesses, then choose the target explicitly
when you need a predictable destination. Restart or reload the harness as needed
for new content. Project trust and provider authentication remain harness settings.

For Pi-native extensions, roles and workflows, follow the [Pi guide](/pi-core).
For explicit Codex source routes and native qualification limits, choose
`core-profile-cx` and follow the [Codex guide](/codex-core).
