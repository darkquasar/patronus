# Spec/plan boundary reference cases

These invented briefs and review subjects support proportionate source inspection
and old/new Claude/Codex observations. They are not a runtime harness, required
run matrix, grader, progress ledger or semantic development gate. Select cases
that illuminate changed seams; reuse observations across requirements. Pi and
OpenCode receive static resource and host-contract inspection only, without
native campaigns or inferred grades.

Use [cases.md](cases.md) with the actual accepted spec and plan for an effort.
Retain baseline bytes before edits, or reconstruct them from the exact Git base
and any captured dirty/untracked inputs. Do not overwrite owner-installed skills.

For an actual comparison, retain in the effort's existing evidence location:

- Brief/case, source root/base/head, relevant dirty/untracked inputs and hashes.
- Separate old/new source snapshots and hashes, selected entry, all loaded
  companions, actual installed paths and a loading trace proving the selected
  bytes were read. A global same-name copy or only one version invalidates a delta.
- Host/model/provider, comparable context, native authority, full prompts and
  full outputs from the same relevant invented brief on each version.
- `worse`, `better` or `same` as a subjective judgment, with concrete old/new
  excerpts, intended outcome and rationale; explain mixed-dimensional tradeoffs.
- Actual commands/exits/logs, omitted cases, and unavailable/invalid evidence.

Use the existing isolated installer procedure and the host's established
authenticated session/loading mechanism. Installer-only HOME/XDG/host directory
variables must not flow into the authenticated session. Never copy credentials,
assume another host's API, silently change models/providers, add trust bypasses or
install tools. Catalog bundles and local/global placement establish resources,
not native loading or behavioral qualification.

Unavailable comparison tooling, a wrong-copy load, an old good answer or a
`worse`/`same` observation does not stop development and is not a pass/fail grade.
Disclose the limitation and retain identities for later use. Binding requirements,
objective project checks and the existing independent review still apply. A new
substantial evaluator or hard gate needs a consequential owner decision covering
purpose/value, evidence, granularity, burden, blocked condition and a simpler
alternative; reuse already settled policy and routine checks without reapproval.
