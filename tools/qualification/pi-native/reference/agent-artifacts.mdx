# Agent artifacts and native adapters

**Status: Pi-native delivery implemented; runtime qualification remains separate.** Baseline `32741e687647e44c4aed071d90965f34d102de52` had no Pi adapter. The current implementation validates/copies finite Patronus-authored Pi resources while delegating exact native package lifecycle to Pi; invented mechanism fixtures cover lifecycle and refusals. Real core roles/content and selected Pi/extension runtime compatibility require separate catalog and deployment evidence. This Mintlify-ready page adds no site, dependency, build or publication. See the [delivery and migration runbook](pi-delivery.md).

## One artifact model, target-specific materialization

```text
versioned agent artifact + declared dependencies + source entry
    -> selected target adapter and its native validation/rendering
    -> owned native file (or explicitly supported configuration effect)
    -> harness discovery, separate trust/loading and observed runtime use
```

Use the existing `family: artifact`, `type: agent`. A Patronus **profile** is a bundle of catalog items, not a runtime persona. Catalog **role** is an installable's classification layer, not an agent's prompt or native invocation mode. A **runtime agent profile** is the native definition a harness consumes. Markdown, TOML and JSON encodings do not by themselves justify another install lifecycle family.

Artifact identity/version/requirements, adapter layout/validation and runtime semantics are separate. Independently maintained native definitions can have target-specific identities and versions; a genuinely portable source can use tested existing transformations. Selection flavors filter catalog identity, not magically swap source bodies. There is no universal model/provider, context/skills, tool/permission or parent-role inheritance translation.

## Implemented Pi adapter contract

Reuse `AgentLayout.Format` with `pi-subagents-markdown`, selected only by the Pi adapter. No new manifest field, family, schema version or controller is required. The native validation/copy branch runs **before** general YAML parsing. Require exact `targets: [pi]`, an explicit safe relative Markdown entry, matching catalog identity/native name/deployed filename stem, required native description and nonempty prompt. The entry can be `agent.md`; it need not share the deployed filename.

The layout has no BodyIs or Frontmatter policy. Reject nonempty supporting `Files` and **any nonempty artifact Overrides**, including another target's override, rather than silently ignoring them. One existing CREATE effect contains exactly the validated source bytes. Missing/legacy/unknown Pi agent format, incompatible layout or native-format/non-Pi pairing fails before the whole selection writes. Existing non-Pi renderers and adapter definitions remain unchanged. Future native targets require an explicit qualified handler, not an unchecked generic raw-file mode.

### Selected Pi native agent subset

This is a deliberately finite Patronus admission contract for pi-subagents0.72.1 on Pi0.87.1, not a universal YAML schema or a reimplementation of the whole upstream loader. All keys outside this table are unsupported in this initial native branch, even where upstream supports them. No default is inserted: omission remains omission, and every admitted source byte is retained.

| Admitted frontmatter keys | Accepted native shape / meaning boundary |
|---|---|
| name, description | Required nonempty single-line native strings; name equals manifest identity and deployed filename stem. Description is native source data, not synthesized from the manifest. |
| model, output | Optional nonempty single-line native strings; model/provider selection and output resolution remain upstream semantics. Core roles omit both: model is inherited and the launcher supplies the exclusive output path. |
| tools, excludeTools, skills | Optional simple unquoted CSV or indented `- item` block lists; an explicitly empty `key:` has zero items, omission stays absent. No flow-list syntax, quoted/escaped list tokens, null/~ tokens or commas within an item. Selected named skills require catalog closure; tools/excludeTools accept ordinary registry names only: reject slash/backslash tokens, .js/.ts suffixes (including bare helper.js/helper.ts), and mcp: direct selectors. Path/module spellings can request executable extensions upstream; that route and static direct-MCP selection are deferred. Named tools do not provision providers or grant OS permission. Optional MCP capabilities remain separately qualified operator-owned native agentOverrides, not an exception to this static-file refusal. |
| extensions, subagentOnlyExtensions, skillPath, defaultReads | Same omitted/empty/list distinction. Any nonempty resource reference must be an absolute path, with no relative/dot-segment, home-expansion or template spelling. Relative references are rejected, not relocated or installed. Initial seven roles omit these fields; launchers supply resolved reads and separately qualified operator-owned overrides enable optional capabilities. Admission never proves that an absolute resource exists, is trusted or is loadable. |
| inheritProjectContext, inheritGlobalContext, inheritSkills, allowNestedSubagents, async, defaultProgress | Literal true/false only; global context true requires project context true. Core explicitly enables the three inheritance fields and sets allowNestedSubagents:false; tool restrictions/prose remain cooperative, not a sandbox. |
| systemPromptMode | replace or append; selected upstream prompt semantics, no parent-role inheritance synthesis. |
| defaultContext | fresh or fork; core/review defaults remain fresh. |
| outputMode | inline or file-only; distinct from an output JSON schema. |
| acceptanceRole | read-only or writer; core writer uses writer, other roles read-only or omit under the core role contract. Native host verification remains separately configured. |
| timeoutMs, toolTimeoutMs | Unquoted positive decimal integers no greater than2147483647 (a conservative admitted subset); not proof of descendant settlement or total cost bounds. |
| maxSubagentDepth | Unquoted nonnegative decimal integer no greater than2147483647; no automatic delegation authority. |
| outputSchema, toolBudget | Unquoted single-line JSON object after the colon; parse as JSON object, not YAML mapping. Reject arrays, null, malformed JSON and duplicate JSON members. Output-schema/tool-budget operational validity is the selected upstream consumer's separate qualification, not a new general schema engine. Core does not need these fields. |

The source is one UTF-8 Markdown file with exact opening/closing `---` delimiter lines, LF or CRLF, unique top-level keys and a nonempty prompt body. Scalar strings may be plain or one matching pair of simple quotes, without escape processing or embedded delimiter quotes; reject ambiguous escape/multiline scalar forms. Block-list items must be contiguous: reject indented comments or blank lines inside a list, and reject any resumed indented item after a column-zero comment/blank separator. Column-zero comments/blanks are allowed only between complete entries, before the first key or after a completed value with no later continuation; after a separator the next nonseparator must be a new top-level key or the closing delimiter. An empty key remains empty when followed by such a separator, never a resumed block. Comments are not transparent YAML whitespace; unsupported continuations, inline comments, anchors/tags, nested maps, folded/literal scalars and malformed delimiters fail rather than silently become prompt text. List items use ordinary nonempty tokens and consistent space indentation. The validator recognizes only these admitted forms; it does not run JavaScript, import upstream modules or serialize general YAML. The native loader may normalize body whitespace/line endings in memory; delivered bytes remain exact.

Named unsupported examples are aliases/package identity, runner/external executables, permission/permissions, nested acceptance/memory, thinking/fast/interactive, fallbackModels and settings-only defaultProvider. Diagnose artifact identity, target, field/line and unsupported/malformed reason with remediation; do not strip, coerce, ignore or claim equivalent permissions. Unknown keys and duplicates fail the whole selected plan before writes. Requalifying an additional native field is explicit future scope, not a new family or universal translation.

## Pi role example

This documents the implemented static role shape; it is not an installed artifact or a launch command. The manifest excerpt omits ordinary required version/role/description fields; a real catalog manifest must satisfy the existing complete manifest schema.

```yaml
family: artifact
type: agent
targets: [pi]
entry: agent.md
files: []
# No artifact Overrides. Identity/version/requires live in the ordinary manifest.
```

Example native `agent.md` for the implemented local-source researcher role:

```markdown
---
name: patronus-researcher-pi
description: Investigate local source and return attributed findings
tools: read, bash
skills: research-team-pi, verification-before-completion-pi
inheritProjectContext: true
inheritGlobalContext: true
inheritSkills: true
allowNestedSubagents: false
defaultContext: fresh
acceptanceRole: read-only
---
Read the assigned brief and source. Return evidence, limitations and an acceptance
report to the exclusive runtime-bound output. Do not edit source or delegate.
```

In the implemented workflow, the runtime can persist the result without granting write/edit tools. Bash is still powerful: this is cooperative source-read-only scope, not an isolation proof. Actual manifest requirements include both named skills and `pi-subagents`. The seven local-source identities are `patronus-researcher-pi`, `patronus-spec-author-pi`, `patronus-technical-reviewer-pi`, `patronus-workflow-security-reviewer-pi`, `patronus-plan-author-pi`, `patronus-plan-reviewer-pi` and `patronus-writer-pi`. They do not replace upstream builtins. The current core profile also requires a web-researcher role and pi-web-access; web is not optional core functionality. Optional MCP remains separately qualified. Intended model inheritance is not a provider-availability guarantee.

Pi global agents resolve beneath `PI_CODING_AGENT_DIR`, otherwise `~/.pi/agent`; local agents go under the explicitly selected workspace `.pi/agents`. Static discovery inspects qualified user/project/local-package/builtin declarations, so placement requires collision checks, not merely writing a file. Executable callbacks and runtime registrations remain visibly runtime-unverified; configured extensions alone are not blanket blockers. Patronus does not run npm root -g; uninspected global npm discovery is runtime-unverified, and PI_OFFLINE is not a mandatory admission gate or network sandbox. Catalog/runtime identity and deployed filename are intentionally equal for these artifacts even where upstream allows otherwise.

## Static ownership, update and removal

Static role delivery uses ordinary owned-file state/checksums. Preview is read-only. Invalid/unsupported selected definitions refuse the whole apply before destination/state/lock writes; no partial skip silently weakens a profile. Update/remove use recorded paths, not a newly changed environment variable. Preserve drifted or unknown files under existing ownership rules; deleting an owned definition is not authority to delete sessions, outputs, memory or shared agent directories. A lower-priority native definition can become visible after removal, so runtime inventory/reload checks remain necessary.

The initial Pi agent branch owns no shared registration/config key. Operator-owned Pi `agentOverrides` is separate from artifact Overrides and can change effective resources/model/context; static validation does not govern those settings. Reversible manual changes require original-byte/config evidence, scope/trust and drift checks. Any later adapter that needs configuration registration must explicitly own its structural leaf/inverse and preserve siblings; this page does not authorize that implementation.

Required core delivery includes real versioned `tk` plus exact `pi-subagents` and `pi-web-access` npm refs, not dependency advice alone; this page does not certify upstream package bytes. Pi host remains external. Pi/npm own package installation, update, removal and package files. Patronus records the exact ref, scope, bounded pending intent and observed selected package metadata, and refuses missing, stale, ambiguous or conflicting dependencies before unrelated local writes. Local removal leaves compatible globals intact. Pi updates require exactly one explicit `--local` or `--global` scope; omission or both flags refuses, while unflagged legacy non-Pi updates retain baseline behavior. Local updates verify global dependencies but never upgrade them; global updates preserve local items. Quiesce all consumers before replacement or removal, delegate the operation to Pi, then confirm the selected declaration/package state before settling intent. Unknown ownership or consumers retain/escalate. No npm-file fingerprint ledger, packages-array controller or reference-counted profile lifetime is implied.

## Declarative roles are not executable extensions

JS/TS modules that register handlers/tools or call `pi-subagents/agents` `registerAgent` execute code. Their registration is process-local, disposable and not automatically inherited by children. This is not native discovery of `agents/researcher.ts`. Deliver and qualify them through existing appropriate recipe/package/plugin lifecycles, including locked dependencies, host peers, trust, loading, quiescence and teardown; never reinterpret them as a static Markdown agent because they define a persona. Opaque delivery does not certify safety or supply missing dependency installation.
